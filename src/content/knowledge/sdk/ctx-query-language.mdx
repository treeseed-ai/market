# `ctx` Query Language

`ctx` is the public graph-query command for TreeSeed AI context retrieval.

It describes the context pack you want, not the low-level search mechanics:

```text
ctx <target>
  [for <stage>]
  [in <scope>]
  [via <relation[,relation...]>]
  [depth <0-3>]
  [where <filter-expression>]
  [limit <n>]
  [budget <tokens>]
  [as <list|brief|full|map>]
```

## Mental Model

`ctx` means:

> build a context pack starting from this target, for this work stage, inside these content scopes, following these graph relationships, under these size and output constraints

The engine resolves roots, traverses the graph, filters nodes, ranks them, and shapes the output.

## Target Selectors

The first argument after `ctx` is the root selector.

```text
ctx "Cloudflare Queue"
ctx @agent-runtime
ctx /knowledge/market/index
ctx #queue
ctx %architecture
```

Supported target forms:

- `"text query"` or bare text: lexical root discovery
- `@id`: canonical graph or content id
- `/path`: content-oriented path
- `#tag`: tag-based root selection
- `%type`: content or node type root selection

If a text target could be confused with a clause keyword such as `for` or `in`, quote it.

## Clauses

### `for`

Stage-aware ranking policy.

```text
for plan
for implement
for research
for debug
for review
```

Behavior:

- `plan`: prefers canonical architecture, objectives, knowledge docs, and decisions
- `implement`: prefers API, schema, guide, example, and section-level material
- `research`: broader exploration with lighter ranking bias
- `debug`: prefers runbooks, troubleshooting material, and nearby implementation docs
- `review`: prefers canonical, superseding, and constraint-heavy docs

### `in`

Restricts results to one or more content path prefixes.

```text
in /knowledge
in /knowledge + /objectives
in /knowledge/market
```

V1 rules:

- each scope path must start with `/`
- multiple scope paths are joined with `+`
- scope paths are content-oriented prefixes, not filesystem globs

### `via`

Limits which graph relationships may be traversed.

```text
via related
via depends_on,implements
via references,parent,child
```

V1 relation vocabulary:

- `related`
- `depends_on`
- `implements`
- `references`
- `parent`
- `child`
- `supersedes`

### `depth`

Traversal depth from the root.

```text
depth 0
depth 1
depth 2
depth 3
```

V1 restricts depth to `0-3`.

### `where`

Simple metadata filters.

```text
where type=architecture
where status=canonical
where audience in (agent,developer)
where tag in (queue,worker)
where domain=infrastructure
```

Supported fields:

- `type`
- `status`
- `audience`
- `tag`
- `domain`

Supported operators:

- `field=value`
- `field in (a,b,c)`

### `limit`

Maximum number of selected nodes.

```text
limit 5
limit 12
```

### `budget`

Maximum token budget for packed output.

```text
budget 3000
budget 6000
```

### `as`

Output shape.

```text
as list
as brief
as full
as map
```

Meaning:

- `list`: minimal node list with almost no text
- `brief`: short excerpts and compressed context
- `full`: larger excerpts within budget
- `map`: graph neighborhood orientation with edge reasons and minimal text

## Defaults

If a clause is omitted, `ctx` uses these defaults:

```text
for plan
via related,references
depth 1
limit 8
as brief
```

`budget` falls back to the runtime default when omitted.

## Examples

Planning:

```text
ctx "Cloudflare Queue" for plan in /knowledge via related,depends_on depth 2 where type in (architecture,objective) limit 8 budget 4000 as brief
```

Implementation:

```text
ctx "Cloudflare Queue" for implement in /knowledge via implements,references,depends_on depth 1 where type in (api,guide,schema,example) limit 10 budget 5000 as full
```

Explicit path:

```text
ctx /knowledge/market/index for implement via child,depends_on depth 1 as brief
```

Canonical id:

```text
ctx @objective:launch-market-site for plan via related,supersedes depth 2 where status=canonical as map
```

Tag-based research:

```text
ctx #queue for research in /knowledge via references,related depth 2 limit 12 budget 7000 as brief
```

Agent-oriented:

```text
ctx "multi-agent worker queue" for plan in /knowledge where audience in (agent,developer) budget 3500 as brief
```

```text
ctx @knowledge:queue-api for implement in /knowledge via implements,references depth 1 budget 4500 as full
```

## Invalid Examples

Old syntax is no longer supported:

```text
root=query:queue depth=2 edges=DEPENDS_ON
```

Malformed `where`:

```text
ctx "queue" where unknown=value
ctx "queue" where status in ()
```

Malformed scope list:

```text
ctx "queue" in knowledge + /objectives
```

Invalid relation:

```text
ctx "queue" via linked_to
```
